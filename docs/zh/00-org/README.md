# 组织治理 — my-ai-guides

目的

本层定义适用于所有使用本仓库的 AI 项目的组织级治理：角色与职责、发布门控、风险分级，以及必须执行的 Battle（红队）频次。

受众：组织负责人、产品负责人、安全/隐私、法务、平台管理员。

负责人

- 组织负责人：@org-owner（请替换）
- 安全 / 红队：@security-team
- 平台：@platform-team

风险矩阵（简要）

- 低风险：无 PII、无外部副作用（只读回答）。走常规 CI 流程。
- 中风险：可能返回敏感业务信息、能建议操作。需要 PR 并运行自动化 battle 子集。
- 高风险：执行外部动作（写 DB、发送邮件、付款）。需要人工审批、沙箱执行与完整 Battle。

发布门控

- 任何影响高风险流程的 prompt 变更必须：
  1. 提交 PR 并标注 `risk:high`
  2. 添加单元测试与 battle 用例
  3. 通过自动化测试与安全扫描
  4. 获得组织负责人或安全团队的明确批准

月度节奏

- 各团队须至少每月运行一次 Battle 子集并将结果上传至 `docs/04-examples/`。

从何开始

- 向 `docs/03-templates/` 提交模板。
- 在 `docs/02-projects/<project-name>/` 下创建项目文档。
